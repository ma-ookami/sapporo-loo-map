# 札幌トイレ・コンビニマップ(Web 版)— 引き継ぎ README

すすきの周辺の **トイレとコンビニ** を地図で探す PWA(スマホ向け)。マスコットはヒグマの「くまトイ」。
ビルドなし(HTML + CSS + JS)、GitHub Pages 向け。リポジトリ: `ma-ookami/sapporo-loo-map`(`main`)。
英語名 Sapporo Loo Map / 日本語名 札幌トイレ・コンビニマップ。iOS ネイティブ版(Expo)は `../sapporo-loo-map`(下の「Expo 版」)。

## 1b. 方針(決定・未着手): 投稿は「申請 → 運営が許可」にする
いたずら対策の本命。**いまの「投稿すると即、全員に出る」形をやめ、トイレの追加は申請にして、運営(ユーザー)が専用画面で許可したものだけを出す。**
- **範囲:** 対象は「トイレの追加」。コンビニの貸し出し報告(借りられる/声かけ/借りられない)と一言報告は、いまのまま即反映でよい(未決定。荒れたら申請制を検討)
- **流れ(案):** ユーザーが＋追加 → 申請(`loo-requests`、状態 pending)→ 本人にだけ「確認中」と表示 → 運営が許可すると `loo-toilets` に入って全員に出る / 却下なら申請を消す
- **専用画面(案):** `admin.html`(別ページ。アプリからはリンクしない)。Google ログインで運営だけ入れる(ルールの許可リストは自分の uid / メールで判定)。申請の一覧(名前・種類・階・料金・メモ・地図上の位置)→ 許可・却下・編集して許可
- **ルール(案):** `loo-requests` は作成=匿名ログイン可(項目・長さ・座標を今と同じ制限)、読む=本人と運営だけ、更新・削除=運営だけ。`loo-toilets` の作成=運営だけ、読む=誰でも。`loo-users`(投稿の間隔)と「ここにはなかった」(`MISS_N`)は、申請制にしたら役目が変わる(申請の連投制限には使える。「なかった」は許可済みの情報の誤りの指摘として残してもよい)
- **決めること:** 申請者への通知方法(画面の「確認中」表示だけで足りるか)/ 運営が複数になる可能性 / 許可前に重複(20m 以内)を運営が見分けられる表示 / 却下理由を本人に見せるか
- **作業順(案):** ① ルールと `cloud.js`(申請の作成・自分の申請の読み取り)② 追加画面の文言を「申請する」に ③ `admin.html` ④ 既存の `loo-toilets` の投稿はそのまま残す ⑤ ルールを貼り直し(要・ユーザー作業)
- 実装前に、この節をユーザーと確認すること

## 2. 機能(画面)
- **個室の数:** 公開データには無い(OSM は 0/40 件に `capacity` 等が無く、札幌市のオープンデータにも個室数のデータは見つからなかった。国や東京都の標準も、一般の個室数は項目に無い)。そのため**利用者に教えてもらう**: 追加画面の「個室の数」(1〜5以上。トイレだけ)と、詳細の「個室はいくつ?」(1・2・3・4・5以上を1タップ。**みんなの中央値(小さいほう)**を、タグ「個室 N」で出す。作った人の入力も1票)。報告は `stall-1`〜`stall-5`(文書 ID `<toiletId>_stall_<uid>`)、追加するトイレの任意の項目 `stalls`(§6)
- **英語表示(Language: English):** 設定の「言語 / Language」で切り替え(読み込み直して反映)。**初めての人は端末の言語で決まる**(日本語以外は英語)。画面の日本語を辞書(`js/i18n-en.js`)で英語に置き換える仕組み(`js/i18n.js`)。地図の文字も同じ設定。場所の名前は、英語の名前(OSM の `name:en`)があれば英語で出し、無ければ日本語のまま。プライバシーのページは `privacy.en.html`(§8 に、文言を足すときの決まり)
- **地下の表示:** OSM の階(`addr:floor` → `level`、日本の「1階」=1・地下1階=-1)を `floor` として取り込む。地下(floor<0)は、タグ「地下 B1」と、ピン右下の「B」の印、凡例の1行。**階が不明な場所は、詳細の「どこにある?」で 地上 / 地下 / 2階以上 を1タップで教えられる**(みんなの多数決。同数は不明のまま)。**コンビニは、ほとんどが地上なので、地下か地上かは扱わない**(B 印・地下タグ・「どこにある?」の質問・追加画面の階の選択は、トイレだけ。データには、コンビニの階も入っているが、画面には出さない)。地下道との距離で地下を推測する方法は、精度が低かったので採らなかった(地下の12件のうち当たったのは3〜7件)
- 階の情報がある場所は、OSM で トイレ 6/40 件(地下 3 件)のみ。残りは利用者に教えてもらうしかない
- **下のシート:** 最寄りカード(1行: くま・名前と距離・「ナビ開始」)→ リスト(広がる)/ 詳細。つまみのタップ・上下スワイプで開閉。地図の何もない所をタップで詳細・リストが閉じる(追加中は無効)
- **フッター:** リスト(押すと開閉)・＋追加・設定。「地図」タブは無い(リストを閉じれば地図)
- **上部:** ブランド名、地図の色の切り替え(重なった四角)、現在地(◎)、絞り込みチップ(横スクロール)
- **左下:** 凡例(4行・小さく半透明。幅 600px 以上は常時表示、スマホは「凡例」ボタンで開閉。トイレ=データ/ユーザー追加(点線は未確認)、コンビニ=借りられる/借りられない)。下のシートに追従、リスト表示中・追加中は隠す
- **絞り込み**(`st.filters`): 上段=種類の切替(すべて / トイレ / コンビニ。`tonly`/`conly`)+「いま空いてる」。2段目は種類に応じて出る: トイレ=無料・車いす・24時間 / コンビニ=借りられる(`conv`)・ブランド(セブン/ファミマ/ローソン/セーコマ)。種類を替えると、前の種類専用の絞り込みは外れる(`syncFilterUi` in settings.js)。初期は「すべて」
  - **コンビニ探しのモード**(コンビニ選択中 / ブランド選択中): 最寄りが「いちばん近いコンビニ」。借りられるか不明・借りられないの店も最寄り/リストに出し、引いた地図(zoom<15)でも不明の店を出す
  - 設定の「画面に出す絞り込みボタン」は廃止(`chips` 設定も無し)
- **詳細:** 階・料金・車いす・営業中タグ・星(使いやすさ/場所のわかりやすさ)・メモ・一言報告(トイレ: きれい/混んでた/使えなかった、24時間だけ集計。コンビニ: 借りられる/声をかけて/借りられない=多数決、同数は声かけ)・お客さん専用等の注意書き・「ここへ行く」(Google マップ徒歩)・自分の追加は削除
- **＋追加:** 現在地にピンを置いた状態で始まる → 動かして「ここにする」→ トイレ/コンビニを選び、名前・階(B1〜10F〜)・料金・車いす / ブランド・貸し出し(借りられる・声をかけて借りる・借りられない)・星・メモ → 登録
- **ピンと色:** 青赤の半々=データのトイレ / **緑=ユーザー追加のトイレ**(右上に人のバッジ。コンビニは貸し出しの丸と重ならないよう、人のバッジは左上)。**確認されるまでは点線**(うすい緑の地+緑のアイコン+緑の点線の枠。コンビニは枠だけ点線)。**作った人以外の 2 人以上**が「行った」報告(きれい/混んでた/使えなかった/地上・地下/個室の数/貸し出し)をすると、濃い緑の実線(`isConfirmed`・`CONFIRM_N`。「ここにはなかった」は数えない。同じ人の重ね報告も 1 人。運営の許可制(§1b)ができたら、許可も確認済みにする)/ コンビニ=塗りと縁がチェーンの薄い色(セブン=赤・ファミマ=緑・ローソン=水色・セーコマ=橙・その他=白。`b-<ブランド>`)+ **右上の丸が貸し出し**(緑=借りられる・橙=声かけ・灰の×=借りられない・なし=不明、不明は少し小さく薄い)/ 黒=選択中 / 最寄りは広がる輪 / 現在地は青い点。ボタン類の橙(`#c4521f`)は「操作」の色
- **「いま空いてる」:** `js/hours.js` が OSM の opening_hours(曜日・時間帯・日またぎ・off)を日本時間で判定。**営業時間が不明なものは出す**(営業時間外と分かるものだけ隠す)
- **設定**(localStorage `loo-settings`): テーマ(自動/ライト/ダーク)・地図の色(シンプル/カラー)・地図の文字(日本語/English)・歩く速さ・振動・最寄りにコンビニも出す・不明のコンビニを地図に出す・絞り込みボタンの出し入れ・自分が追加したもの/報告の一覧と削除・使う前に/プライバシー/連絡/版/この端末の記録を消す
- **地図:** OpenFreeMap。シンプル=`positron`(暗い時 `dark`)/ カラー=`bright`(暗い時 `fiord`)。地名は1言語だけ(日本語=name:ja→name、English=name_en→name:latin→name)。店アイコン・道路標識・住所番号は消す(`tidyStyle`)
- **現在地:** 許可がないとき◎でトーストに理由(iPhone の設定の場所)。最初に取れたとき、地図を動かしておらずすすきの 3km 以内なら寄る。遠い(最寄り 1.5km 超)ときは「すすきのへ」ボタン
- **初回の案内「使う前に」:** お客さん専用のトイレもある / できるだけ買い物を・混雑時は遠慮・声かけの言い方 / 情報は投稿。出典(© OpenStreetMap contributors)と位置情報の説明、`privacy.html` へのリンク付き。**文言は私(エージェント)の案なので、ユーザーに確認してもらうこと**
- **名前のないトイレ:** 「トイレ(○○ 付近)」(近くの施設・通りの名前)。26 件中 20 件が名前なし、16 件に目印が付く

## 6. 保存先(Firebase playground)
- `loo-reports` の kind: `clean`/`crowded`/`closed`/`missing`(状態。文書 ID `<toiletId>_<uid>`)、`loan-yes`/`loan-ask`/`loan-no`(貸し出し。同上)、`lv-gr`/`lv-ug`/`lv-up`(どの階?。文書 ID `<toiletId>_lv_<uid>`。状態の報告と別の文書なので、両方出せる)
- PaP と同じ `playground-d8897`。コレクション `loo-toilets`(追加されたトイレ。項目: name,lat,lng,fee,wheelchair,floor,ease,find,type,brand,loan,note,uid,createdAt)と `loo-reports`(一言報告。ID=`<toiletId>_<uid>`、kind: clean/crowded/closed/loan-yes/loan-ask/loan-no)。匿名ログインで書く。読むのは誰でも、削除・取り消しは本人だけ。他のアプリと衝突しないよう `loo-` を付けている
- **ルールの足し方:** Firebase コンソール → Firestore → ルール →「`documents` の中」に `firestore.playground-snippet.rules` の match 2つを足して公開。**他のアプリのルールが入っているなら完全版は貼らない**(消える)。匿名ログインの有効化と承認済みドメイン `ma-ookami.github.io` も確認
- ルール: `loo-toilets` の ID は英数字 20 文字だけ許可(ID を使った XSS 対策)。**ルールを変えたので、コンソールに貼り直す**
- 荒らし対策: ルールで項目・長さ・ID の形式・座標(すすきの〜札幌駅、緯度 43.03〜43.09・経度 141.32〜141.38。画面の `AREA`/`inArea` と同じ)を制限。**投稿の間隔(30 秒に1件・24時間に10件)はルールが見張る**: `loo-users/{uid}`(lastAt,n,windowStart,lastId)をトイレ追加と同じバッチで更新し、`loo-toilets` の create が `getAfter` で照合(`cloud.add`)。画面側にも同じ制限と、20m 以内の重複確認。**「ここにはなかった」(kind: missing)が 3 人(`MISS_N`)集まった追加情報は、薄く表示して最寄り・リストから外す(消さない)**。App Check・通報は未実装

## 7. 開発・確認
- **テストは短く、変更に関係する 1〜2 本だけ**(ユーザーの方針。全部を連続で回さない。1 本が数分かかる)。例: ピンの見た目 → 見た目を調べる短いスクリプト / 追加・報告 → `test-userpin` / 文言を足した → `i18n-capture` と `test-i18n`(文言を足したときだけ)
- 追加のテスト: `test-floor`(地下の表示・階の報告)/ `test-i18n`(英語: 端末の言語で初期表示、主な画面に日本語が残っていない、言語の切り替え。写真 `tools/shot-en-*.png` も撮る)。**どのテストも、端末の言語を日本語にして動かす(`locale: 'ja-JP'`)。** 英語の端末だと自動で英語になるため
- 動かす: `index.html` を直接開く(`file://` では位置情報は取れない。公開 URL か localhost で)
- テスト: `node tools/test-xxx.js`。playwright-core は `../taskline/node_modules` を借りる。ブラウザ(Chrome か Edge。`tools/browser.js` が選ぶ。環境変数 LOO_BROWSER で指定も可)を GPU 無しで動かすため **1本が 1〜5 分かかる**。バックグラウンドで実行して完了を待つ。**Edge を全部終了させるコマンドは使わない**(ユーザーのブラウザが落ちる)

## 8. はまりどころ(同じ失敗をしないように)
- **画面の文言を足す・変えるとき(英語表示):** 日本語で書けば、画面に出るときに辞書で英語になる。辞書に無い文言は日本語のまま出る。**(1)** `node tools/i18n-capture.js`(英語で画面をひととおり操作して、辞書に無い文言を `tools/_missing.json` に書く。数分かかる)**(2)** `tools/i18n-build-dict.js` に `D('日本語の先頭', '英語')` を足して `node tools/i18n-build-dict.js` で `js/i18n-en.js` を作り直す(キーは `_keys.json`/`_missing.json`/`_strings.json` に実在するものだけ。一覧に無い新しい文言は `ADD`)**(3)** `node tools/test-i18n.js` で、日本語が残っていないか確認
- **場所の名前・メモなど利用者やデータの文字には `translate="no"` を付ける**(辞書で訳さない。付け忘れると、たまたま辞書と同じ文字の名前が英語になる)。名前を文章に埋め込むときは `I18N.t('…{name}…',{name})`(辞書のキーは、その文字列のまま)。場所の名前は `nameOf(t)`(英語のときは `name_en`)を使う
- 辞書の英語では、数字を `{n}`(順番どおり)か `{1}` `{2}`(順番を入れ替え)で戻す。数字が文の中に混ざる文言は、数字の部分が `{n}` になって辞書を引かれる
- **地図スタイルの入れ替えは `reloadStyle()`(`setStyle(url,{diff:false})`)。** 差分更新だと `style.load` が来ず `tidyStyle` が動かず、日英併記・店アイコン・標識が戻る
- **MapLibre のマーカー外側の要素に CSS の `transform` を付けない**(位置指定に使われる)。動きは内側の `.pi` に付ける
- **`index.html` の `?v=` スタンプ:** `node tools/stamp.js` が各ファイルのハッシュを付ける。`.git/hooks/pre-commit` で自動実行(**フックは git に入らない**。別 PC は `node tools/stamp.js && git add index.html` を置く)。パッチで `<script src="js/ui.js"></script>` のように完全一致で探すと外れる(先頭だけで探す)
- **シェルのヒアドキュメントはバックスラッシュを壊す。** 長いコードはファイルツール(Write)で書く。改行は `String.fromCharCode(10)`、正規表現のエスケープは避ける
- **Node の `/tmp` と bash の `/tmp` は別の場所**(Node は `C:\tmp`)。一時ファイルはプロジェクト内に置くか、プロジェクト外のスクラッチパッドを使う
- ヘッドレスでは、地図を拡大(zoom 16 以上)すると描画が数十秒かかる。テストは zoom 15.5 前後で
- **高さに `vh` を直接使わない。** iPhone の Safari は、アドレスバーがあるあいだ `vh` が見えている高さより大きく、下に寄せたパネル(設定・シート)の上の端が画面の外に出て、閉じるボタンが押せなくなる。`js/main.js` が `--vh`(= innerHeight/100)を作るので、css では `calc(var(--vh,1vh)*92)` のように使う(`node tools/test-settings-close.js`。Edge が起動しないときは Chrome の `executablePath` に替える)
- iOS Safari は `navigator.vibrate` 非対応(振動は Android のみ)。位置情報は https 必須、`file://` 不可
- git の「LF will be replaced by CRLF」の警告は無害
- `st.filters` のキーを増やすときは、`index.html` のボタン(2段目は `data-g=t|c`)と `map.js` の `st.filters`・`passes` をそろえる
